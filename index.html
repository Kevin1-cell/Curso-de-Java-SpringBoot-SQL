📦 1.1 — ¿Cómo funciona Java? JVM, JDK, JRE Día 1

🏦 ¿Por qué Java en Bancolombia? Bancolombia tiene más de 20M de clientes, procesa millones de transacciones diarias. Java lleva 30+ años dominando sistemas financieros críticos porque: es robusto, seguro, multiplataforma, tiene el ecosistema empresarial más maduro del mundo y Spring Boot lo convierte en la herramienta perfecta para microservicios bancarios.

La cadena de ejecución:

  • Tu código (.java) → lo escribes tú
  • javac (compilador) → transforma a bytecode (.class)
  • JVM (Java Virtual Machine) → ejecuta el bytecode en cualquier OS
  • JDK = JVM + compilador + herramientas de desarrollo
  • JRE = solo JVM + librerías (para ejecutar, no desarrollar)

📦 1.4 — Métodos: el arte de organizar el código

public class MetodosBancarios {

    // Método sin retorno
    public static void imprimirSeparador(String titulo) {
        System.out.println("\n" + "=".repeat(40));
        System.out.println("  " + titulo.toUpperCase());
        System.out.println("=".repeat(40));
    }

    // Método con retorno simple
    public static double calcularInteresSimple(double capital, double tasaAnual, int meses) {
        return capital * tasaAnual * meses / 12.0;
    }

    // Método con validación
    public static double calcularCuotaMensual(double monto, double tasaMensual, int plazo) {
        if (monto <= 0) throw new IllegalArgumentException("Monto debe ser > 0");
        if (tasaMensual <= 0) throw new IllegalArgumentException("Tasa debe ser > 0");
        if (plazo <= 0) throw new IllegalArgumentException("Plazo debe ser > 0");

        // Fórmula de cuota nivelada (crédito bancario real)
        double factor = Math.pow(1 + tasaMensual, plazo);
        return monto * (tasaMensual * factor) / (factor - 1);
    }

    // Sobrecarga (mismo nombre, diferente firma)
    public static double calcularInteresSimple(double capital, double tasaAnual) {
        return calcularInteresSimple(capital, tasaAnual, 12); // llama al anterior
    }

    // Varargs — cantidad variable de parámetros
    public static double sumarTransacciones(double... montos) {
        double total = 0;
        for (double m : montos) total += m;
        return total;
    }

    public static void main(String[] args) {
        imprimirSeparador("Simulador de Crédito");

        double cuota = calcularCuotaMensual(10_000_000, 0.018, 24); // 10M, 1.8% mes, 24 cuotas
        System.out.printf("Cuota mensual: $%,.2f%n", cuota);

        double interes = calcularInteresSimple(5_000_000, 0.08);
        System.out.printf("Interés anual: $%,.2f%n", interes);

        double totalDia = sumarTransacciones(500_000, 200_000, -100_000, 1_500_000);
        System.out.printf("Total movimientos: $%,.2f%n", totalDia);
    }
}

import java.util.*;
import java.util.stream.*;

public class ColeccionesYStreams {
    public static void main(String[] args) {

        // ============ ARRAYLIST ============
        List<Double> transacciones = new ArrayList<>(List.of(
            500_000.0, -200_000.0, 1_500_000.0, -300_000.0, 800_000.0
        ));
        transacciones.add(250_000.0);
        transacciones.remove(0); // elimina por índice
        System.out.println("Transacciones: " + transacciones);

        // ============ HASHMAP ============
        Map<String, Double> saldosPorCuenta = new HashMap<>();
        saldosPorCuenta.put("CA-001", 1_500_000.0);
        saldosPorCuenta.put("CC-002", 5_200_000.0);
        saldosPorCuenta.put("CDT-003", 10_000_000.0);

        // Iterar sobre el mapa
        saldosPorCuenta.forEach((cuenta, saldo) ->
            System.out.printf("  %s → $%,.2f%n", cuenta, saldo)
        );

        // Buscar o default
        double saldo = saldosPorCuenta.getOrDefault("CA-999", 0.0);
        System.out.println("Saldo CA-999: $" + saldo); // 0.0

        // ============ STREAMS API ============
        List<Double> movimientos = List.of(
            500_000.0, -200_000.0, 800_000.0, -50_000.0, 1_200_000.0, -400_000.0
        );

        // Filtrar solo consignaciones (positivos)
        List<Double> consignaciones = movimientos.stream()
            .filter(m -> m > 0)
            .collect(Collectors.toList());
        System.out.println("Consignaciones: " + consignaciones);

        // Suma total
        double totalIngresos = movimientos.stream()
            .filter(m -> m > 0)
            .mapToDouble(Double::doubleValue)
            .sum();
        System.out.printf("Total ingresos: $%,.2f%n", totalIngresos);

        // Convertir lista de números a lista de Strings formateados
        List<String> formateados = movimientos.stream()
            .map(m -> String.format("$%,.0f", m))
            .collect(Collectors.toList());
        System.out.println("Formateados: " + formateados);

        // Encontrar el mayor retiro
        Optional<Double> mayorRetiro = movimientos.stream()
            .filter(m -> m < 0)
            .min(Double::compareTo);
        mayorRetiro.ifPresent(r -> System.out.printf("Mayor retiro: $%,.0f%n", r));

        // Agrupar por tipo
        Map<String, List<Double>> agrupados = movimientos.stream()
            .collect(Collectors.groupingBy(m -> m > 0 ? "CONSIGNACION" : "RETIRO"));
        agrupados.forEach((tipo, lista) ->
            System.out.println(tipo + ": " + lista.size() + " transacciones")
        );
    }
}

🎯 QUIZ SEMANA 1 — 30 Preguntas de Entrevista Java

Responde en voz alta. Pasa el cursor sobre cada pregunta para ver la respuesta.

  1. ¿Cuál es la diferencia entre JDK, JVM y JRE?
    JDK = Kit de desarrollo (compilador + JVM + herramientas). JVM = Máquina virtual que ejecuta bytecode. JRE = Entorno de ejecución (JVM + librerías). Para desarrollar necesitas JDK. Para solo ejecutar, JRE.
  2. ¿Por qué se dice que Java es "Write Once, Run Anywhere"?
    Porque el compilador genera bytecode (.class) que no es específico de ningún sistema operativo. La JVM de cada OS interpreta ese mismo bytecode. El código Java compila una sola vez y corre en cualquier máquina que tenga JVM.
  3. ¿Cuáles son los 8 tipos primitivos de Java?
    byte, short, int, long (enteros) | float, double (decimales) | char (carácter) | boolean (verdadero/falso). IMPORTANTE: String NO es primitivo, es una clase.
  4. ¿Por qué no se debe usar double para representar dinero?
    Por imprecisión de punto flotante en binario. 0.1 + 0.2 = 0.30000000000000004. En sistemas financieros esto es inaceptable. Se debe usar BigDecimal que tiene precisión exacta para decimales.
  5. ¿Qué diferencia hay entre == y .equals() en Java?
    == compara referencias (si dos variables apuntan al mismo objeto en memoria). .equals() compara el contenido. Para Strings siempre usa .equals(). Ejemplo: new String("hola") == new String("hola") → FALSE, pero "hola".equals("hola") → TRUE.
  6. ¿Qué es el Garbage Collector?
    Es el proceso automático de la JVM que libera la memoria de objetos que ya no tienen referencias activas. En C/C++ el programador libera memoria manualmente. Java lo hace automáticamente, reduciendo memory leaks.
  7. ¿Qué significa que Java es fuertemente tipado?
    Que debes declarar explícitamente el tipo de cada variable y Java verifica los tipos en tiempo de compilación. No puedes asignar un String a un int sin conversión explícita. Esto previene errores en tiempo de ejecución.
  8. ¿Cuál es la diferencia entre ArrayList y LinkedList?
    ArrayList: internamente es un array dinámico. Acceso rápido por índice O(1). Inserción/eliminación en medio O(n). LinkedList: lista de nodos enlazados. Acceso por índice O(n). Inserción/eliminación al inicio O(1). Usa ArrayList por defecto, LinkedList solo si insertas/eliminas mucho al inicio.
  9. ¿Qué es un NullPointerException y cómo evitarlo?
    Ocurre cuando intentas llamar un método o acceder a un campo de una variable que es null. Evitarlo: validar siempre antes de usar (if (obj != null)), usar Optional<T>, o anotar con @NonNull de Lombok.
  10. Explica la diferencia entre checked y unchecked exceptions.
    Checked: el compilador te obliga a manejarlas (try/catch o declarar throws). Ej: IOException, SQLException. Unchecked (RuntimeException): no es obligatorio manejarlas. Ej: NullPointerException, IllegalArgumentException. En Spring Boot generalmente se usan unchecked.
  11. ¿Qué es el Stack y el Heap en Java?
    Stack: memoria para variables locales y llamadas a métodos. Cada hilo tiene su propio stack. Heap: memoria compartida donde se almacenan los objetos. El Garbage Collector limpia el heap. Las referencias de variables locales viven en el stack, pero los objetos a los que apuntan viven en el heap.
  12. ¿Qué es autoboxing en Java?
    La conversión automática entre tipos primitivos y sus clases wrapper. int ↔ Integer, double ↔ Double, boolean ↔ Boolean. Java lo hace automáticamente: List<Integer> lista = new ArrayList<>(); lista.add(5); // 5 se convierte a Integer automáticamente.
  13. ¿Qué hace el modificador final?
    En variable: no se puede reasignar (constante). En método: no se puede sobreescribir. En clase: no se puede heredar. Ej: final double PI = 3.14159; — nunca cambia.
  14. ¿Qué es un método estático (static)?
    Un método que pertenece a la CLASE, no a una instancia. Se llama directamente: MiClase.metodo() sin crear objeto. Útil para métodos utilitarios como Math.sqrt(), Collections.sort(). No puede acceder a atributos de instancia.
  15. ¿Qué diferencia hay entre String, StringBuilder y StringBuffer?
    String: inmutable — cada concatenación crea un nuevo objeto (costoso en loops). StringBuilder: mutable, más eficiente para concatenar, NO thread-safe. StringBuffer: igual que StringBuilder pero thread-safe (sincronizado). Usa StringBuilder en casi todos los casos.

    cu.saldo,

FROM clientes c
JOIN cuentas cu ON c.id = cu.cliente_id
JOIN tipos_cuenta tc ON cu.tipo_cuenta_id = tc.id
LEFT JOIN transacciones t ON (t.cuenta_origen_id = cu.id OR t.cuenta_destino_id = cu.id)
LEFT JOIN tipos_transaccion tt ON t.tipo_transaccion_id = tt.id
WHERE c.numero_documento = '1094456789'

ORDER BY t.fecha DESC;

-- ============ AGREGACIONES ============
-- Resumen de cartera por segmento
SELECT
    c.segmento,
    COUNT(DISTINCT c.id) AS total_clientes,
    COUNT(cu.id) AS total_cuentas,
    SUM(cu.saldo) AS cartera_total,
    AVG(cu.saldo) AS saldo_promedio,
    MAX(cu.saldo) AS mayor_saldo
FROM clientes c
LEFT JOIN cuentas cu ON c.id = cu.cliente_id AND cu.estado = 'ACTIVA'
WHERE c.activo = TRUE
GROUP BY c.segmento
HAVING COUNT(cu.id) > 0
ORDER BY cartera_total DESC;

-- ============ WINDOW FUNCTIONS (avanzado — muy preguntado) ============
-- Ranking de cuentas por saldo + porcentaje del total
SELECT
    c.nombres || ' ' || c.apellidos AS cliente,
    cu.numero_cuenta,
    cu.saldo,
    RANK() OVER (ORDER BY cu.saldo DESC) AS ranking,
    ROUND(
        cu.saldo * 100.0 / SUM(cu.saldo) OVER ()
    , 2) AS pct_cartera,
    SUM(cu.saldo) OVER (ORDER BY cu.saldo DESC) AS acumulado
FROM cuentas cu
JOIN clientes c ON cu.cliente_id = c.id
WHERE cu.estado = 'ACTIVA';

-- Comparar saldo actual vs mes anterior (lag)
SELECT
    DATE_TRUNC('month', fecha)::DATE AS mes,
    SUM(CASE WHEN cuenta_origen_id IS NOT NULL THEN monto ELSE 0 END) AS total_debitos,
    SUM(CASE WHEN cuenta_destino_id IS NOT NULL THEN monto ELSE 0 END) AS total_creditos,
    LAG(SUM(monto)) OVER (ORDER BY DATE_TRUNC('month', fecha)) AS mes_anterior,
    SUM(monto) - LAG(SUM(monto)) OVER (ORDER BY DATE_TRUNC('month', fecha)) AS variacion
FROM transacciones
WHERE estado = 'COMPLETADA'
GROUP BY DATE_TRUNC('month', fecha)
ORDER BY mes;

-- ============ SUBCONSULTAS ============
-- Clientes con saldo por encima del promedio del segmento
SELECT c.nombres, c.segmento, cu.saldo
FROM clientes c
JOIN cuentas cu ON c.id = cu.cliente_id

    JOIN clientes c2 ON cu2.cliente_id = c2.id

🎯 QUIZ SEMANA 2 — Preguntas SQL para Entrevista

  1. ¿Qué diferencia hay entre INNER JOIN, LEFT JOIN y FULL OUTER JOIN?
    INNER JOIN: solo registros que tienen coincidencia en ambas tablas. LEFT JOIN: todos los registros de la tabla izquierda, con NULL donde no hay coincidencia en la derecha. FULL OUTER JOIN: todos los registros de ambas tablas, con NULL donde no hay coincidencia. En banca: LEFT JOIN para reportes que muestran clientes aunque no tengan cuentas.
  2. ¿Qué son las propiedades ACID y por qué son críticas en banca?
    A=Atomicidad (todo o nada), C=Consistencia (BD siempre en estado válido), I=Isolation (transacciones no se interfieren), D=Durabilidad (datos guardados permanecen). En banca: si falla una transferencia a mitad, gracias a ACID el dinero no desaparece — se hace ROLLBACK automático.
  3. ¿Qué es un índice y cuándo se debe crear uno?
    Un índice es una estructura de datos adicional que acelera búsquedas en la tabla (como el índice de un libro). Crea índice en columnas que usas frecuentemente en WHERE, JOIN, ORDER BY. Desventaja: ocupa espacio y ralentiza INSERT/UPDATE. En banca: siempre indexar numero_documento, numero_cuenta, fecha_transaccion.
  4. ¿Qué diferencia hay entre WHERE y HAVING?
    WHERE filtra filas ANTES de agrupar (no puede usar funciones de agregación). HAVING filtra DESPUÉS de GROUP BY (puede usar COUNT, SUM, etc.). Ejemplo: WHERE saldo > 0 filtra antes. HAVING COUNT(*) > 5 filtra grupos con más de 5 registros.
  5. ¿Qué es normalización de base de datos? ¿Qué es 3FN?
    Proceso de organizar tablas para eliminar redundancia y dependencias problemáticas. 1FN: sin grupos repetitivos, cada celda tiene un solo valor. 2FN: sin dependencias parciales (todo depende de la clave completa). 3FN: sin dependencias transitivas (atributos no clave no dependen entre sí). En banca: el nombre del cliente no va en la tabla de cuentas, va en clientes y se relaciona por FK.
  6. ¿Cómo evitarías una condición de carrera en una transferencia bancaria?
    Con SELECT ... FOR UPDATE que bloquea las filas de las cuentas durante la transacción. Ninguna otra transacción puede modificarlas hasta que se haga COMMIT o ROLLBACK. Así si dos transferencias intentan usar el mismo saldo al mismo tiempo, una espera a que la otra termine.
  7. Si tienes 3 tablas: clientes, cuentas y transacciones, ¿cómo obtienes el total de transacciones por cliente del último mes?
    SELECT c.nombres, COUNT(t.id) as total_tx, SUM(t.monto) as total_monto FROM clientes c JOIN cuentas cu ON c.id = cu.cliente_id JOIN transacciones t ON cu.id = t.cuenta_origen_id WHERE t.fecha >= CURRENT_DATE - INTERVAL '30 days' GROUP BY c.id, c.nombres ORDER BY total_tx DESC;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import java.math.BigDecimal;
import java.time.LocalDateTime;
import java.util.UUID;

@Service
@RequiredArgsConstructor
@Slf4j
public class TransaccionServiceImpl implements TransaccionService {

    private final CuentaRepository cuentaRepository;
    private final TransaccionRepository transaccionRepository;
    private final NotificacionService notificacionService;

    @Value("${banco.gmf.tasa:0.004}")
    private BigDecimal tasaGMF; // 4x1000

    @Value("${banco.limite.transferencia:50000000}")
    private BigDecimal limiteTransferencia;

    @Override
    @Transactional(rollbackFor = Exception.class) // rollback en CUALQUIER excepción
    public TransaccionResponseDTO realizarTransferencia(TransferenciaRequestDTO request) {
        log.info("Iniciando transferencia. Origen: {}, Destino: {}, Monto: {}",
                request.getCuentaOrigen(), request.getCuentaDestino(), request.getMonto());

        // 1. Validar límites de negocio
        if (request.getMonto().compareTo(limiteTransferencia) > 0) {
            throw new LimiteExcedidoException(
                "Monto supera límite diario de " + limiteTransferencia);
        }

        // 2. Cargar cuentas con bloqueo pesimista (evita condición de carrera)
        Cuenta origen = cuentaRepository.findByNumeroCuentaWithLock(request.getCuentaOrigen())
                .orElseThrow(() -> new CuentaNotFoundException(request.getCuentaOrigen()));

        Cuenta destino = cuentaRepository.findByNumeroCuentaWithLock(request.getCuentaDestino())
                .orElseThrow(() -> new CuentaNotFoundException(request.getCuentaDestino()));

        // 3. Validaciones de negocio
        if (origen.getEstado() != EstadoCuenta.ACTIVA) {
            throw new CuentaBloqueadaException("Cuenta origen no está activa: " + origen.getEstado());
        }
        if (origen.getId().equals(destino.getId())) {
            throw new BusinessException("No se puede transferir a la misma cuenta");
        }
        if (origen.getSaldo().compareTo(request.getMonto()) < 0) {
            throw new SaldoInsuficienteException(origen.getSaldo(), request.getMonto());
        }

        // 4. Calcular GMF si aplica
        BigDecimal gmf = BigDecimal.ZERO;
        if (origen.getTipoCuenta().isCobraGMF()) {
            gmf = request.getMonto().multiply(tasaGMF);
        }
        BigDecimal totalDebito = request.getMonto().add(gmf);

        // 5. Ejecutar transferencia
        origen.setSaldo(origen.getSaldo().subtract(totalDebito));
        origen.setSaldoDisponible(origen.getSaldoDisponible().subtract(totalDebito));
        origen.setFechaUltimoMovimiento(LocalDateTime.now());

        destino.setSaldo(destino.getSaldo().add(request.getMonto()));
        destino.setSaldoDisponible(destino.getSaldoDisponible().add(request.getMonto()));
        destino.setFechaUltimoMovimiento(LocalDateTime.now());

        cuentaRepository.save(origen);
        cuentaRepository.save(destino);

        // 6. Registrar transacción
        Transaccion transaccion = Transaccion.builder()
                .referencia(UUID.randomUUID().toString())
                .cuentaOrigen(origen)
                .cuentaDestino(destino)
                .monto(request.getMonto())
                .gmf(gmf)
                .descripcion(request.getDescripcion())
                .canal(request.getCanal())
                .estado(EstadoTransaccion.COMPLETADA)
                .build();
        transaccion = transaccionRepository.save(transaccion);

        // 7. Notificar (asíncrono — no bloquea la respuesta)
        notificacionService.notificarTransferencia(origen.getCliente().getEmail(),
                transaccion.getReferencia(), request.getMonto());

        log.info("Transferencia completada. Ref: {}", transaccion.getReferencia());

        return TransaccionResponseDTO.builder()
                .referencia(transaccion.getReferencia())
                .monto(transaccion.getMonto())
                .gmf(transaccion.getGmf())
                .nuevoSaldoOrigen(origen.getSaldo())
                .estado("COMPLETADA")
                .fecha(transaccion.getFecha())
                .build();
    }
}

🎯 QUIZ SEMANA 3 — Spring Boot para Entrevista

  1. ¿Qué es Spring Boot y qué problema resuelve sobre Spring Framework?
    Spring Framework es un ecosistema de librerías para Java empresarial. Spring Boot es una capa encima que agrega: autoconfiguración (configura automáticamente según dependencias), servidor embebido (no necesitas instalar Tomcat), starter dependencies (agrupa dependencias comunes) y opinionated defaults. Spring Boot reduce la configuración XML o Java manual de Spring a casi cero. En vez de 200 líneas de config, Spring Boot lo infiere automáticamente.
  2. ¿Qué es la Inyección de Dependencias y por qué es mejor que crear objetos con new?
    La IoC (Inversión de Control) invierte quién crea y administra los objetos: en vez de que tu clase cree sus dependencias con new, Spring las crea y las inyecta. Ventajas: fácil testing (puedes inyectar mocks), bajo acoplamiento (la clase no sabe cómo se creó su dependencia), ciclo de vida administrado. Spring recomienda inyección por constructor sobre @Autowired en campo.
  3. ¿Cuál es la diferencia entre @Component, @Service y @Repository?
    Los tres registran la clase como bean de Spring. La diferencia es semántica y de comportamiento adicional: @Component: genérico. @Service: indica que contiene lógica de negocio (sin comportamiento adicional). @Repository: indica acceso a datos + Spring convierte excepciones de persistencia a DataAccessException automáticamente.
  4. ¿Qué diferencia hay entre FetchType.LAZY y FetchType.EAGER en JPA?
    LAZY: los datos relacionados se cargan solo cuando se accede a ellos (bajo demanda). EAGER: los datos relacionados se cargan inmediatamente junto con la entidad principal. En banca: si un cliente tiene miles de transacciones, usar EAGER cargaría todo al traer el cliente — muy ineficiente. Usa siempre LAZY para colecciones (@OneToMany) y solo EAGER para relaciones simples (@ManyToOne) cuando siempre las necesitas.
  5. ¿Qué es @Transactional y qué pasa si no lo uso en una transferencia?
    @Transactional envuelve el método en una transacción de base de datos. Si algo falla dentro, se hace ROLLBACK automático — ningún cambio queda guardado. Sin @Transactional: si el crédito a cuenta destino falla después del débito a origen, el dinero desaparece. Con @Transactional: si cualquier parte falla, Spring hace ROLLBACK de todo. Usar siempre en operaciones que modifican datos.
  6. ¿Por qué no se debe exponer una Entity JPA directamente como respuesta de la API?
    1. Seguridad: la entidad puede tener campos sensibles (contraseña, datos internos). 2. Acoplamiento: si cambias la BD, rompes el contrato de la API. 3. Problemas de serialización: relaciones LAZY causan LazyInitializationException al serializar a JSON. 4. Rendimiento: podrías serializar datos innecesarios. Solución: usar DTOs (Data Transfer Objects) que contienen solo lo que necesita el cliente.
  7. Si tienes 3 tablas en BD y usas JPA, ¿cómo modelarías las relaciones?
    Ejemplo con clientes-cuentas-transacciones: Cliente → @OneToMany → List<Cuenta> (un cliente tiene muchas cuentas). Cuenta → @ManyToOne → Cliente (cada cuenta pertenece a un cliente). Cuenta → @OneToMany → List<Transaccion>. Transaccion → @ManyToOne → Cuenta. En código: el lado "uno" usa mappedBy para indicar que el otro lado tiene la FK. El lado "muchos" tiene @JoinColumn con el nombre de la columna FK en BD.
  8. ¿Qué es un @ControllerAdvice y por qué es mejor que try/catch en cada controller?
    Es una clase global que intercepta excepciones de TODOS los controllers. Sin él: duplicas el manejo de errores en cada método. Con @ControllerAdvice: defines una vez cómo manejar SaldoInsuficienteException y aplica a toda la aplicación automáticamente. Además centraliza el formato de respuesta de error, asegurando consistencia en toda la API.

// 2. JWT SERVICE
@Service
@Slf4j
public class JwtService {

    @Value("${jwt.secret}") private String secret;
    @Value("${jwt.expiration:86400000}") private long expiration; // 24h

    private Key getKey() {
        return Keys.hmacShaKeyFor(Base64.getDecoder().decode(secret));
    }

    public String generarToken(UserDetails user) {
        Map<String, Object> claims = new HashMap<>();
        claims.put("rol", ((Usuario) user).getRol().name());
        claims.put("banco", "Bancolombia");

        return Jwts.builder()
                .claims(claims)
                .subject(user.getUsername())
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + expiration))
                .signWith(getKey())
                .compact();
    }

    public String extraerUsername(String token) {
        return getClaims(token).getSubject();
    }

    public boolean esValido(String token, UserDetails user) {
        try {
            String username = extraerUsername(token);
            return username.equals(user.getUsername()) && !estaExpirado(token);
        } catch (JwtException e) {
            log.warn("Token inválido: {}", e.getMessage());
            return false;
        }
    }

    private boolean estaExpirado(String token) {
        return getClaims(token).getExpiration().before(new Date());
    }

    private Claims getClaims(String token) {
        return Jwts.parser().verifyWith((SecretKey) getKey())
                .build().parseSignedClaims(token).getPayload();
    }
}

// 3. FILTRO JWT
@Component
@RequiredArgsConstructor
@Slf4j
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            chain.doFilter(request, response); // sin token, pasa sin autenticar
            return;
        }

        String token = authHeader.substring(7); // quitar "Bearer "

        try {
            String username = jwtService.extraerUsername(token);

            if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
                UserDetails user = userDetailsService.loadUserByUsername(username);

                if (jwtService.esValido(token, user)) {
                    UsernamePasswordAuthenticationToken auth =
                        new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
                    auth.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                    SecurityContextHolder.getContext().setAuthentication(auth);
                    log.debug("Usuario autenticado: {}", username);
                }
            }
        } catch (Exception e) {
            log.error("Error procesando JWT: {}", e.getMessage());
        }

        chain.doFilter(request, response);
    }
}

🎯 QUIZ SEMANA 4 — Preguntas Avanzadas para Filtro Bancolombia

  1. ¿Qué diferencia hay entre autenticación y autorización?
    Autenticación: verificar QUIÉN eres (login con usuario/contraseña → obtener token). Autorización: verificar QUÉ puedes hacer (¿tienes permiso de ver esta cuenta? ¿puedes hacer transferencias?). En Spring Security: la autenticación la maneja el login/JWT. La autorización la manejan los roles con hasRole() y @PreAuthorize.
  2. ¿Cómo funciona JWT internamente? ¿Qué tiene un token?
    JWT tiene 3 partes separadas por punto: Header.Payload.Signature. Header: tipo (JWT) y algoritmo (HS256). Payload: claims = datos del usuario (username, rol, expiración) — cualquiera puede leerlos con base64. Signature: hash(Header+Payload+SecretKey) — solo el servidor puede verificarla. Si alguien modifica el payload, la firma no coincide y el token es inválido.
  3. ¿Qué es stateless en el contexto de Spring Security + JWT?
    Sin estado (stateless) significa que el servidor NO guarda información de sesión del usuario entre peticiones. En sesiones clásicas: el servidor guarda la sesión en memoria. Con JWT: el token contiene toda la información necesaria. El servidor solo verifica la firma del token en cada petición, sin consultar ninguna base de datos de sesiones. Esto permite escalar horizontalmente (muchos servidores sin compartir estado).
  4. ¿Cuáles son los verbos HTTP y cuándo usar cada uno en una API REST?
    GET: obtener recursos (sin modificar nada). POST: crear nuevo recurso. PUT: actualizar recurso completo (reemplaza todo). PATCH: actualizar parcialmente (solo los campos enviados). DELETE: eliminar recurso. En APIs REST bancarias: GET /cuentas (listar), POST /cuentas (crear), GET /cuentas/{id} (consultar), PATCH /cuentas/{id}/estado (cambiar estado), DELETE /cuentas/{id} (cancelar).
  5. ¿Qué son los códigos de estado HTTP más importantes?
    200 OK: éxito. 201 Created: recurso creado (POST exitoso). 204 No Content: éxito sin cuerpo (DELETE). 400 Bad Request: datos inválidos (validación fallida). 401 Unauthorized: no autenticado (sin token o token inválido). 403 Forbidden: autenticado pero sin permiso. 404 Not Found: recurso no existe. 409 Conflict: conflicto (ej: cuenta ya existe). 422 Unprocessable: lógica de negocio falla (saldo insuficiente). 500 Internal Server Error: error del servidor.
  6. ¿Qué es TDD (Test Driven Development)?
    Metodología donde escribes el test ANTES de escribir el código. Ciclo: 1) Escribe test que falle (RED). 2) Escribe el mínimo código para que pase (GREEN). 3) Refactoriza manteniendo tests verdes (REFACTOR). Beneficios: código más limpio, mejor diseño, cobertura garantizada. En Bancolombia los equipos de calidad exigen mínimo 80% de cobertura de tests.
  7. ¿Cuál es la diferencia entre un test unitario y un test de integración?
    Test unitario: prueba UNA unidad de código aislada (un método, una clase) con todas las dependencias mockeadas. Rápido, no necesita BD. Test de integración: prueba la interacción entre múltiples componentes reales (controller + service + repository + BD). Más lento, más realista. En Spring: @WebMvcTest para controller, @DataJpaTest para repository, @SpringBootTest para integración completa.
  8. ¿Qué es Mockito y para qué sirve @Mock vs @InjectMocks?
    Mockito es un framework para crear "dobles" de objetos en tests. @Mock: crea un objeto falso de la clase — puedes definir qué retorna cuando llamas sus métodos (when/thenReturn). @InjectMocks: crea la instancia real de la clase bajo prueba e inyecta automáticamente todos los @Mock declarados. Ejemplo: @Mock CuentaRepository repo; @InjectMocks CuentaServiceImpl service; → service tendrá el repo falso inyectado.

☕ JAVA — Preguntas frecuentes

  1. ¿Qué es la Programación Orientada a Objetos? Explica sus 4 pilares.
    POO organiza el código en objetos que tienen estado (atributos) y comportamiento (métodos). Los 4 pilares: ENCAPSULAMIENTO: ocultar la implementación interna (private + getters/setters). HERENCIA: una clase hija reutiliza y extiende la clase padre (extends). POLIMORFISMO: el mismo método tiene diferente comportamiento según el objeto (override). ABSTRACCIÓN: simplificar la complejidad, mostrar solo lo necesario (interfaces, clases abstractas).
  2. ¿Cuándo usas una clase abstracta vs una interfaz?
    Clase abstracta: cuando las clases comparten código común (implementación parcial), cuando hay herencia única y quieres una jerarquía clara. Tiene constructores, puede tener campos con estado. Interfaz: cuando defines un CONTRATO de comportamiento sin importar la jerarquía. Una clase puede implementar MÚLTIPLES interfaces. En Java 8+ las interfaces pueden tener default methods. Regla: interfaz para "qué puede hacer", abstracta para "qué ES".
  3. ¿Qué es el patrón Singleton? ¿Dónde lo usa Spring?
    Singleton garantiza que una clase tenga solo UNA instancia en toda la aplicación. Spring aplica Singleton a todos sus beans por defecto — un solo CuentaService, un solo CuentaRepository para toda la aplicación. Esto ahorra memoria y es seguro porque los beans de Spring no deben tener estado mutable.
  4. ¿Qué es el patrón Repository?
    Patrón que abstrae la capa de acceso a datos. En vez de escribir SQL directamente en el service, creas una interfaz Repository que encapsula todas las operaciones de BD. El service solo llama métodos del repository sin saber si usa SQL, MongoDB o un archivo. Spring Data JPA implementa este patrón automáticamente con JpaRepository.
  5. ¿Qué es Optional en Java y por qué se usa?
    Optional<T> es un contenedor que puede o no tener un valor. Fuerza al programador a manejar el caso "no encontrado" explícitamente. En vez de retornar null (causa NullPointerException), retornas Optional.empty(). El consumidor debe llamar .orElse(), .orElseThrow() o .ifPresent() — no puede ignorar el caso null. Muy usado en repositories: Optional<Cuenta> findByNumeroCuenta(String numero).
  6. ¿Qué son los Generics y para qué sirven?
    Los generics permiten crear clases y métodos que funcionen con cualquier tipo de dato sin sacrificar la seguridad de tipos. List<String> vs List<Integer> — el mismo List pero tipado. Sin generics tendrías que hacer cast manual y podrías mezclar tipos. En APIs bancarias: ApiResponse<T> que puede ser ApiResponse<CuentaDTO> o ApiResponse<String>.
  7. ¿Qué es la concurrencia en Java? ¿Cuándo puede ser un problema?
    Concurrencia = múltiples hilos ejecutando código al mismo tiempo. Problema clásico: race condition — dos hilos leen el mismo saldo (1,000,000), ambos descuentan 500,000 y ambos guardan 500,000. El saldo final es 500,000 pero debería ser 0 (se perdió un retiro). Soluciones: synchronized, ReentrantLock, o en BD: SELECT FOR UPDATE. En Spring Boot con @Transactional + bloqueo pesimista se maneja automáticamente.
  8. ¿Qué diferencia hay entre HashMap y TreeMap?
    HashMap: sin orden, O(1) para get/put, permite una clave null. TreeMap: ordenado por clave (orden natural o comparator), O(log n) para get/put. Usa HashMap para acceso rápido cuando no importa el orden (buscar cuenta por número). Usa TreeMap cuando necesitas orden (reportes ordenados por monto, fechas).

    9. 🌱 SPRING BOOT — Preguntas frecuentes

  9. ¿Qué es un Bean en Spring?
    Un Bean es un objeto creado y administrado por el contenedor IoC de Spring. Spring controla su creación, configuración, ciclo de vida y destrucción. Se definen con @Component, @Service, @Repository, @Controller o @Bean. Por defecto son Singleton (una sola instancia por contexto). Spring inyecta automáticamente las dependencias entre beans.
  10. ¿Qué es @SpringBootApplication?
    Es una anotación compuesta que combina tres anotaciones: @SpringBootConfiguration (la clase es fuente de configuración Spring), @EnableAutoConfiguration (activa la autoconfiguración de Spring Boot según el classpath), @ComponentScan (escanea el paquete y subpaquetes buscando beans anotados). Es el punto de entrada de cualquier app Spring Boot.
  11. ¿Cómo funciona la autoconfiguración de Spring Boot?
    Spring Boot revisa las dependencias en el classpath. Si encuentra spring-boot-starter-data-jpa y un driver de BD, configura automáticamente el DataSource, EntityManagerFactory, TransactionManager, etc. Lo hace a través de clases @Configuration condicionales (@ConditionalOnClass). Puedes sobreescribir cualquier auto-configuración en application.properties.
  12. ¿Qué hace @Transactional exactamente detrás de escenas?
    Spring usa AOP (Programación Orientada a Aspectos) para crear un proxy de la clase. Cuando llamas un método @Transactional, en realidad llamas al proxy que: 1) Inicia una transacción de BD (o une la existente). 2) Ejecuta tu método. 3) Si todo OK → COMMIT. 4) Si hay RuntimeException → ROLLBACK. Importante: @Transactional no funciona si llamas el método desde la misma clase (self-invocation) porque no pasa por el proxy.
  13. ¿Qué es Spring Actuator?
    Módulo que expone endpoints de monitoreo y gestión de la aplicación. /actuator/health: estado de la app (UP/DOWN). /actuator/metrics: métricas de JVM, HTTP, BD. /actuator/info: información de la versión. /actuator/env: propiedades del entorno. En Bancolombia los equipos de operaciones monitorean constantemente estos endpoints con herramientas como Dynatrace o Prometheus.
  14. ¿Por qué usar Flyway o Liquibase?
    Son herramientas de migración de base de datos. Mantienen un historial versionado de cambios en el esquema de BD (como Git para la BD). Problema sin ellas: el equipo hace cambios manuales en BD y no hay control de quién cambió qué. Con Flyway: cada cambio es un script SQL versionado (V1__crear_clientes.sql, V2__agregar_campo_email.sql). Se ejecutan automáticamente al iniciar la app. Fundamental en ambientes multi-developer.

    15. 🗄️ SQL — Preguntas frecuentes

  15. ¿Qué es una Foreign Key y por qué es importante?
    Una Foreign Key (llave foránea) es una columna que referencia la PRIMARY KEY de otra tabla. Garantiza integridad referencial: no puedes crear una cuenta para un cliente que no existe, y no puedes eliminar un cliente que tiene cuentas. En BD bancaria: cuentas.cliente_id → clientes.id. Si intentas insertar una cuenta con cliente_id=999 y ese cliente no existe, la BD rechaza la operación.
  16. ¿Qué es una vista (VIEW) en SQL?
    Una vista es una consulta SELECT guardada con nombre que se puede usar como si fuera una tabla. No almacena datos, los obtiene de las tablas base cada vez que se consulta. Ventajas: simplifica consultas complejas, seguridad (dar acceso a la vista sin acceso directo a la tabla), abstracción. En banca: CREATE VIEW v_extracto_cliente AS SELECT ... (join de 4 tablas) — el equipo de reportes usa la vista sin conocer la complejidad.
  17. ¿Qué diferencia hay entre una función y un procedimiento almacenado en SQL?
    Función: retorna un valor, se puede usar en SELECT, no modifica datos. Ejemplo: calcular_interes(cuenta_id) RETURNS decimal. Procedimiento almacenado: puede modificar datos, puede retornar múltiples resultados, no se usa en SELECT. Ejemplo: realizar_cierre_mensual(). En PostgreSQL ambos se crean con CREATE FUNCTION, pero los procedimientos usan CALL para ejecutarse.

    18. 🏦 CULTURA Y ARQUITECTURA

  18. ¿Qué es un microservicio? ¿Qué diferencia tiene con una aplicación monolítica?
    Monolítico: toda la aplicación en un solo proceso. Fácil de desarrollar inicialmente, difícil de escalar y mantener cuando crece. Microservicio: la aplicación dividida en servicios pequeños e independientes, cada uno con su propia BD. Ventajas: escalar solo el servicio que necesita más recursos, equipos independientes, tecnologías diferentes por servicio. Desventajas: complejidad de red, transacciones distribuidas. Bancolombia tiene cientos de microservicios.
  19. ¿Qué es CI/CD?
    CI (Continuous Integration): los desarrolladores integran código frecuentemente (varias veces al día). Cada integración dispara automáticamente: compilación, tests, análisis de código (SonarQube). CD (Continuous Delivery/Deployment): el código aprobado se despliega automáticamente a ambientes de prueba o producción. En Bancolombia usan GitHub Actions o Jenkins para el pipeline de CI/CD. Como Junior, tu código debe pasar todos los tests antes de hacer merge.
  20. ¿Qué es Docker y por qué lo usan los bancos?
    Docker empaqueta una aplicación con todas sus dependencias en un contenedor. El contenedor corre igual en cualquier ambiente (dev, pruebas, producción). En banca: elimina el "en mi máquina funciona". Los microservicios corren en contenedores Docker orquestados por Kubernetes. Como Junior debes saber crear un Dockerfile básico y usar docker-compose para levantar el stack local.
  21. ¿Qué es un API REST? ¿Cuáles son sus principios?
    REST (Representational State Transfer) es un estilo arquitectural para APIs. Principios: 1) Stateless: cada petición tiene todo lo que necesita, el servidor no guarda estado de cliente. 2) Client-Server: separación clara. 3) Uniform Interface: URIs identifican recursos, verbos HTTP indican acción. 4) Cacheable: las respuestas pueden cachearse. 5) Layered System: el cliente no sabe si habla con el servidor real o un proxy. RESTful = API que sigue estos principios.
  22. ¿Qué es el Principio SOLID?
    S: Single Responsibility — una clase hace una sola cosa. O: Open/Closed — abierto para extensión, cerrado para modificación. L: Liskov Substitution — las subclases deben poder reemplazar a su padre. I: Interface Segregation — interfaces pequeñas y específicas, no una grande. D: Dependency Inversion — depende de abstracciones, no de implementaciones concretas (inyección de dependencias). Spring Boot facilita SOLID al promover inyección de dependencias e interfaces.
  23. ¿Qué harías si encuentras un bug crítico en producción que afecta a miles de clientes?
    Respuesta que buscan: 1) Identificar y aislar el problema (logs, monitoreo). 2) Comunicar inmediatamente al líder técnico y product owner. 3) Evaluar si hay un rollback posible (versión anterior). 4) Si es urgente, hotfix: rama directa de main, fix mínimo, tests, deploy rápido. 5) Post-mortem: ¿qué falló?, ¿qué test faltó?, ¿cómo prevenirlo? Nunca actuar solo en producción sin comunicar.
  24. ¿Cómo aprendes nuevas tecnologías?
    Respuesta honesta y estructurada: documentación oficial (mi primera fuente), tutoriales de Baeldung para Spring, práctica inmediata construyendo algo real (no solo ver videos). GitHub de proyectos open source para ver cómo lo hacen en producción. Comunidades: Stack Overflow, grupos de Java Colombia. Para ti: menciona este curso y tus proyectos en GitHub como evidencia de aprendizaje autodidacta.
